# AIM 

AIM is a combination of rules-based curly arrow generation and an ML-filter to classify the feasibility of those arrows to generate chemical reaction mechanisms. The algorithm can be used step-wise via a web app but also locally to search for paths between two molecules.

## Project Structure

- `SPArrow/`: Core scripts for searching reaction pathways.
- `shared/`: Shared utilities, including reaction rules (`rules.py`), ML helpers, and molecular fingerprinting.
- `scripts/`: Various utility scripts for analyzing mechanisms and fingerprints.
- `models/`: XGBoost models used for classifying arrows.
- `data/`: Datasets and reference files.
- `molecule-web-app`: Web app

## Installation

This project uses Conda for environment management. You can create the environment using:

```bash
conda env create -f environment.yaml
conda activate aim
```

Key dependencies include:
- RDKit
- anytree
- xgboost
- scikit-learn
- matplotlib

## Using SPArrow/test_rxn.py

`test_rxn.py` is a script designed to test the pathway discovery for a single reaction. It calls the `run_parallel` function to search for a mechanism that connects a set of starting SMILES to a set of product SMILES.

### How to use:

1.  **Edit the script**: Open `aim/SPArrow/test_rxn.py` and modify the following variables:
    -   `sm_smiles`: The SMILES string for your starting materials (e.g., `"COC(=O)C=C(N)C.COC(=O)C(C(=O)C)=Cc1ccccc1.[OH3+]"`)
    -   `end_smiles`: The SMILES string for your desired product(s).
    -   **Note**: You do **not** need to manually atom-map your SMILES; the `run_parallel` function handles this automatically.

2.  **Configure Search Parameters**:
    -   `depth_limit`: Maximum number of reaction steps to search (default: 3 or 5).
    -   `no_duplicates`: Whether to avoid duplicate states (default: `True`).
    -   `aromatic`: Enable/disable considering the reactivity of aromatic bonds (default: `True`).
    -   `force_depth`: If `True`, continues searching even after a product is found (default: `False`).
    -   `follow_on_enabled`: Enables follow-on rule application (default: `True`).

3.  **Run the script**:
    ```bash
    python aim/SPArrow/test_rxn.py
    ```

### Required Files

The search engine requires the following files to be present in the project root:
-   `unique_bitvectors.txt`: A list of known reaction fingerprints. # Note to self - remove from final algorithm
-   `models/v116/xg_model.json`: The XGBoost model used for scoring reaction steps (or other models depending on configuration).

### Outputs

When the search completes, it generates:
-   **Terminal Output**: Logs of each step and the time taken.
-   **Pickle Files**: Saved search trees (e.g., `backup_jobname_0.pkl`) containing the discovered pathways.
-   **Text Files**: A visual representation of the tree structure and mechanisms in a `.txt` file.

## Data and Machine Learning

### Training and Finetuning Structure

The `training/` and `finetuning/` directories contain the datasets used to train the XGBoost models. Both follow a consistent hierarchical structure:

-   **Numbered Subdirectories (e.g., `training/112/`, `finetuning/500/`)**: Each directory represents a single reaction state or decision point during a mechanism search.
    -   `sm.pkl`: The starting material(s) for this specific step.
    -   `mol_N.pkl`: Potential product molecules generated by applying reaction rules.
    -   `data.json`: A mapping of the potential mechanisms to labels. It includes:
        -   `choices`: A dictionary where each key corresponds to a `mol_N.pkl` and contains the `mechanism` (rule parameters) and whether it was marked as `probable` (1 for positive example, 0 for negative, or `null` if unlabeled).
        -   `contributor`: The name of the reaction or the person who labeled the data.

### Model Retraining

The `retrain/` directory contains scripts for updating the models based on new data in the `training/` or `finetuning/` folders.

- `retrain/v112/`: Specific version of the retraining logic.
- `bitvectors.csv`: Compiled fingerprints and labels used for model training.

## Other SPArrow Scripts

-   `test_rxns.py`: Bulk testing of multiple reactions from a CSV file (e.g., USPTO dataset).
-   `visualise.py`: Generates PNG images of the discovered reaction pathways from the saved pickle files.
-   `run_parallel.py`: The core engine that performs the parallelized search.

## Environment Variables

-   `SLURM_JOB_ID`: Used for naming output files. Defaults to `backup`.
-   `SCRATCH`: The directory where temporary and output files are saved. Defaults to the current working directory.
